# Agentic Experience

Momentarise Markdown Editor treats agent support as a documentation surface, not a hidden product claim.

The public docs site is built from the same Markdown files that humans read. Agent actions copy or open that Markdown with explicit instructions, so an assistant can reason from the durable source instead of a lossy web scrape.

## What Ships Now

- raw Markdown for every page at `/docs/<page>.md`;
- copy page as Markdown;
- copy current section from the page outline;
- copy page as an LLM prompt;
- Open-in-chat entries for common assistant tools, with copy fallback when a deep link is unreliable;
- generated `llms.txt` and `llms-full.txt`;
- `@momentarise/md-cli` checks for local and agent-driven workflows.

## Prompt Contract

Every copied prompt includes the page content plus rules for safe use:

- use web search if available;
- prefer official docs;
- cite sources when browsing;
- respect MME's Markdown-as-source constraint;
- do not assume JSON or block database persistence;
- separate framework-neutral guidance from host-specific integration.

Markdown remains the source. The prompt is a transport format.

## Files For Agents

`llms.txt` is the short index. It lists important pages and stable URLs.

`llms-full.txt` is the larger context bundle. It concatenates public Markdown pages in navigation order and keeps page boundaries visible.

Both files are generated by `scripts/generate-llms.mjs` and checked by `npm run test:llms-sync`.

## CLI Workflow

Use `@momentarise/md-cli` when an agent needs machine-readable local proof:

```bash
node packages/md-cli/dist/index.js inspect README.md --json
node packages/md-cli/dist/index.js check --json
node packages/md-cli/dist/index.js format README.md
```

The CLI resolves Document Access Policy before it reads, formats, exports, or writes. It is meant to make local automation safer, not to bypass host rules.

## Not Shipped Yet

Generated Codex skills, reusable agent action descriptors, hosted Ask AI, semantic docs search, and edit-on-GitHub style actions are future public-release work.

Do not describe those as current MME capabilities until they are promoted into an implementation issue and proven.
